# 文章审阅指南

按请求选取审阅层次。先处理结论和结构，再处理措辞；给出具体位置、原因和建议，不为满足清单而制造问题。

## 内容与证据

- 检查关键结论能否由引用、推导或实际实验支持，明确适用范围。
- 检查公式前提、符号、维度和推导是否一致，区分定义、近似和工程约定。
- 对源码行为标明项目、版本或 commit 与文件，不将版本未知的摘录泛化。
- 对实验说明输入、方法和结果；没有实验时不虚构性能数字或视觉对比。
- 核验实际依赖的原始来源。内部笔记可作研究入口，不能代替公开读者所需的证据。
- 说明未决问题是阻碍核心结论、需要收窄表述，还是可以移出本篇。

## 结构与语言

- 检查开篇是否明确读者问题，章节是否逐步支持主结论。
- 检查必要前提是否先于推导出现，删去与主线无关的旁支。
- 保持中文简洁、英文标识符准确、术语与坐标约定一致。
- 保留关键解释和中间步骤，不为缩短篇幅跳过必要推理。
- 删除依赖聊天上下文的表达、不可访问的双链和未经提供的作者经历。

## 图示与页面

- 检查图是否有明确解释目的、来源或生成依据、可读标注与图注。
- 核查外部图或改绘图的使用依据；生成图是否记录源文件或可重建的方法。引用来源本身不代表获得使用许可。
- 检查公式、代码、图片、链接和章节层次的实际渲染，不仅检查源文件。
- 草稿阶段用开发预览检查新文章，不把排除草稿后的生产测试当作新文章验收。
- 获准发布后按根目录规范检查生产文章及 canonical、RSS、sitemap，完成部署与线上检查。

## 报告方式

修订已发布文章时，核查结论变化是否有必要的公开纠错说明，原发布日期和路径是否保持稳定，以及本轮验证是否对应当前修改。区分线上版本与未发布修订；不要仅凭存在发布地址报告修订已上线。

先报告影响正确性或理解的问题，再列必要的语言建议。区分已核验、推断与未核验内容，说明实际检查范围。仅审阅请求不自动改稿，修改请求则落实修改并报告结果。
